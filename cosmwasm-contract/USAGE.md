# Инструкция по использованию системы распределения токенов

## Обзор

Этот контракт CosmWasm реализует систему распределения токенов с валидацией заданий. Система позволяет:
- Регистрировать участников
- Принимать задания от участников
- Валидировать задания держателем эмиссионного кошелька (issuer)
- Автоматически распределять по 1 токену каждому участнику после валидации

## Архитектура

### Участники процесса

1. **Issuer (Держатель эмиссионного кошелька)** - адрес, который:
   - Инициализирует контракт
   - Пополняет баланс контракта токенами
   - Валидирует задания участников

2. **Participant (Участник)** - адреса, которые:
   - Регистрируются в системе
   - Подают задания
   - Получают токены после валидации

### Жизненный цикл участника

```
1. RegisterParticipant → участник регистрируется
2. SubmitTask → участник подает задание
3. ValidateTask → issuer валидирует задание
4. ClaimReward → участник получает 1 токен
```

## Детальная инструкция

### 1. Инициализация контракта

**Функция:** `instantiate`

**Параметры:**
- `issuer` (String) - адрес держателя эмиссионного кошелька
- `total_tokens` (u128) - общее количество токенов для распределения (например, 100)
- `denom` (String) - деноминация токена (например, "uatom", "uosmo")

**Пример через Keplr:**
```json
{
  "issuer": "cosmos1abc...",
  "total_tokens": "100",
  "denom": "uatom"
}
```

### 2. Пополнение баланса контракта

**Функция:** `deposit`

**Кто может вызвать:** только issuer

**Описание:** Issuer отправляет токены на баланс контракта для последующего распределения.

**Как использовать в Keplr:**
1. Откройте Keplr Wallet
2. Выберите сеть (Cosmos Hub, Osmosis и т.д.)
3. Перейдите в раздел "Interact with Contract"
4. Выберите контракт
5. Выберите функцию `deposit`
6. **ВАЖНО:** При вызове функции также отправьте токены:
   - В поле "Amount" укажите количество (например, 100000000uatom для 100 ATOM)
   - В поле "Denom" укажите деноминацию (uatom)
7. Подтвердите транзакцию

**Пример JSON:**
```json
{
  "deposit": {}
}
```
При вызове этой функции необходимо также отправить токены в транзакции.

### 3. Регистрация участника

**Функция:** `register_participant`

**Кто может вызвать:** любой адрес (для регистрации самого себя)

**Описание:** Участник регистрируется в системе.

**Как использовать в Keplr:**
1. Участник открывает Keplr Wallet
2. Подключается к сети
3. Переходит в "Interact with Contract"
4. Выбирает функцию `register_participant`
5. Подтверждает транзакцию

**Пример JSON:**
```json
{
  "register_participant": {}
}
```

### 4. Подача задания участником

**Функция:** `submit_task`

**Кто может вызвать:** зарегистрированный участник

**Параметры:**
- `description` (Option<String>) - опциональное описание задания

**Описание:** Участник сообщает, что выполнил задание.

**Как использовать в Keplr:**
1. Участник открывает Keplr Wallet
2. Переходит в "Interact with Contract"
3. Выбирает функцию `submit_task`
4. Опционально указывает описание задания
5. Подтверждает транзакцию

**Пример JSON:**
```json
{
  "submit_task": {
    "description": "Выполнил задание по проверке контракта"
  }
}
```

или без описания:
```json
{
  "submit_task": {
    "description": null
  }
}
```

### 5. Валидация задания issuer

**Функция:** `validate_task`

**Кто может вызвать:** только issuer

**Параметры:**
- `participant` (String) - адрес участника, задание которого валидируется

**Описание:** Issuer вручную проверяет задание участника и валидирует его.

**Как использовать в Keplr:**
1. Issuer открывает Keplr Wallet
2. Переходит в "Interact with Contract"
3. Выбирает функцию `validate_task`
4. Указывает адрес участника
5. Подтверждает транзакцию

**Пример JSON:**
```json
{
  "validate_task": {
    "participant": "cosmos1xyz..."
  }
}
```

### 6. Получение токена участником

**Функция:** `claim_reward`

**Кто может вызвать:** участник с валидированным заданием

**Описание:** Участник получает 1 токен с баланса контракта после того, как его задание было валидировано.

**Как использовать в Keplr:**
1. Участник открывает Keplr Wallet
2. Переходит в "Interact with Contract"
3. Выбирает функцию `claim_reward`
4. Подтверждает транзакцию
5. Токен автоматически отправляется на адрес участника

**Пример JSON:**
```json
{
  "claim_reward": {}
}
```

## Запросы (Queries)

### 1. Получить конфигурацию

**Функция:** `get_config`

**Возвращает:**
- `issuer` - адрес issuer
- `total_tokens` - общее количество токенов
- `denom` - деноминация
- `tokens_distributed` - количество уже распределенных токенов
- `tokens_remaining` - оставшиеся токены

**Пример JSON:**
```json
{
  "get_config": {}
}
```

### 2. Получить статус участника

**Функция:** `get_participant_status`

**Параметры:**
- `participant` (String) - адрес участника

**Возвращает:**
- Статус участника (registered, task_submitted, validated, token_claimed)
- Информацию о задании

**Пример JSON:**
```json
{
  "get_participant_status": {
    "participant": "cosmos1xyz..."
  }
}
```

### 3. Получить информацию о задании

**Функция:** `get_task_info`

**Параметры:**
- `participant` (String) - адрес участника

**Возвращает:**
- Детальную информацию о задании участника

**Пример JSON:**
```json
{
  "get_task_info": {
    "participant": "cosmos1xyz..."
  }
}
```

### 4. Получить список участников

**Функция:** `list_participants`

**Параметры:**
- `start_after` (Option<String>) - адрес для пагинации
- `limit` (Option<u32>) - лимит результатов (максимум 100)

**Пример JSON:**
```json
{
  "list_participants": {

  }

```

### 5. Получить статистику

**Функция:** `get_stats`

**Возвращает:**
- Общую статистику по контракту

**Пример JSON:**
```json
{
  "get_stats": {}
}
```

## Полный пример сценария использования

### Шаг 1: Issuer инициализирует контракт
```json
{
  "issuer": "cosmos1issuer...",
  "total_tokens": "100",
  "denom": "uatom"
}
```

### Шаг 2: Issuer пополняет баланс контракта
Вызывает `deposit` и отправляет 100 токенов (100000000uatom) на контракт.

### Шаг 3: Участники регистрируются
Каждый из 100 участников вызывает `register_participant`.

### Шаг 4: Участники подают задания
Каждый участник вызывает `submit_task` после выполнения задания.

### Шаг 5: Issuer валидирует задания
Issuer проверяет каждое задание вручную и вызывает `validate_task` для каждого валидного задания.

### Шаг 6: Участники получают токены
После валидации участник вызывает `claim_reward` и получает 1 токен.

## Важные замечания

1. **Безопасность:**
   - Только issuer может валидировать задания и пополнять баланс
   - Участник может получить токен только после валидации своего задания
   - Каждый участник может получить только 1 токен

2. **Ограничения:**
   - Максимальное количество токенов задается при инициализации
   - Если все токены распределены, новые заявки не будут обработаны

3. **Валидация:**
   - Валидация происходит вручную issuer через Keplr
   - Issuer должен проверять задания вне блокчейна
   - После валидации участник может получить токен

4. **Баланс контракта:**
   - Токены должны быть на балансе контракта перед вызовом `claim_reward`
   - Issuer может пополнять баланс постепенно по мере необходимости

## Использование через CLI (для разработки)

Если вы используете CLI вместо Keplr, примеры команд:

```bash
# Инициализация
wasmd tx wasm instantiate $CODE_ID '{"issuer":"cosmos1issuer...","total_tokens":"100","denom":"uatom"}' --label "token-distribution" --admin $ISSUER_ADDR --from $ISSUER_KEY --chain-id $CHAIN_ID

# Пополнение баланса
wasmd tx wasm execute $CONTRACT_ADDR '{"deposit":{}}' --amount 100000000uatom --from $ISSUER_KEY --chain-id $CHAIN_ID

# Регистрация участника
wasmd tx wasm execute $CONTRACT_ADDR '{"register_participant":{}}' --from $PARTICIPANT_KEY --chain-id $CHAIN_ID

# Подача задания
wasmd tx wasm execute $CONTRACT_ADDR '{"submit_task":{"description":"Выполнил задание"}}' --from $PARTICIPANT_KEY --chain-id $CHAIN_ID

# Валидация задания
wasmd tx wasm execute $CONTRACT_ADDR '{"validate_task":{"participant":"cosmos1participant..."}}' --from $ISSUER_KEY --chain-id $CHAIN_ID

# Получение токена
wasmd tx wasm execute $CONTRACT_ADDR '{"claim_reward":{}}' --from $PARTICIPANT_KEY --chain-id $CHAIN_ID
```
