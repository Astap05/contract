# Система распределения токенов CosmWasm

## Описание проекта

Этот контракт CosmWasm реализует систему распределения токенов с валидацией заданий. Система позволяет держателю эмиссионного кошелька распределять токены между участниками после выполнения и валидации их заданий.

## Функциональность

### Основные возможности:

1. **Инициализация контракта**
   - Issuer (держатель эмиссионного кошелька) настраивает контракт
   - Указывает общее количество токенов и их деноминацию

2. **Регистрация участников**
   - Любой адрес может зарегистрироваться как участник

3. **Подача заданий**
   - Участники подают задания после их выполнения
   - Опционально указывают описание задания

4. **Валидация заданий**
   - Issuer вручную проверяет и валидирует задания участников
   - Это происходит в ручном режиме через Keplr

5. **Получение токенов**
   - После валидации участник получает 1 токен автоматически
   - Токены отправляются с баланса контракта на адрес участника

## Ключевые компоненты

### State (src/state.rs)

- `Config` - Конфигурация контракта (issuer, total_tokens, denom)
- `ParticipantStatus` - Статусы участника (Registered, TaskSubmitted, Validated, TokenClaimed)
- `TaskInfo` - Информация о задании участника
- Хранилища:
  - `CONFIG` - Конфигурация
  - `PARTICIPANTS` - Мапа участников и их статусов
  - `TASKS` - Мапа заданий участников
  - `TOKENS_DISTRIBUTED` - Счетчик выданных токенов

### Messages (src/msg.rs)

**Execute:**
- `RegisterParticipant` - Регистрация участника
- `SubmitTask` - Подача задания
- `ValidateTask` - Валидация задания (только issuer)
- `ClaimReward` - Получение токена
- `Deposit` - Пополнение баланса контракта (только issuer)

**Query:**
- `GetConfig` - Получить конфигурацию
- `GetParticipantStatus` - Статус участника
- `GetTaskInfo` - Информация о задании
- `ListParticipants` - Список всех участников
- `GetStats` - Общая статистика

### Contract Logic (src/contract.rs)

**Execute функции:**
1. `instantiate` - Инициализация контракта
2. `register_participant` - Регистрация участника
3. `submit_task` - Подача задания участником
4. `validate_task` - Валидация задания issuer
5. `claim_reward` - Получение токена участником
6. `deposit` - Пополнение баланса контракта

**Query функции:**
1. `get_config` - Получить конфигурацию
2. `get_participant_status` - Статус участника
3. `get_task_info` - Информация о задании
4. `list_participants` - Список участников
5. `get_stats` - Статистика

## Процесс работы

### Сценарий использования:

1. **Инициализация**
   ```
   Issuer → instantiate(issuer, total_tokens: 100, denom: "uatom")
   ```

2. **Пополнение баланса**
   ```
   Issuer → deposit() + отправка 100 токенов на контракт
   ```

3. **Регистрация участников**
   ```
   Participant1 → register_participant()
   Participant2 → register_participant()
   ...
   Participant100 → register_participant()
   ```

4. **Подача заданий**
   ```
   Participant1 → submit_task(description: "Выполнил задание")
   Participant2 → submit_task(description: "Выполнил задание")
   ...
   ```

5. **Валидация заданий (вручную через Keplr)**
   ```
   Issuer → validate_task(participant: "cosmos1participant1...")
   Issuer → validate_task(participant: "cosmos1participant2...")
   ...
   ```

6. **Получение токенов**
   ```
   Participant1 → claim_reward() → получает 1 токен
   Participant2 → claim_reward() → получает 1 токен
   ...
   ```

## Безопасность

- ✅ Только issuer может валидировать задания
- ✅ Только issuer может пополнять баланс контракта
- ✅ Участник может получить токен только после валидации
- ✅ Каждый участник может получить только 1 токен
- ✅ Проверка баланса контракта перед выдачей токена
- ✅ Защита от повторного получения токена

## Запросы (Queries)

Все запросы доступны для чтения состояния контракта:

- `get_config` - Текущая конфигурация и количество распределенных токенов
- `get_participant_status` - Статус конкретного участника
- `get_task_info` - Детальная информация о задании
- `list_participants` - Список всех участников с пагинацией
- `get_stats` - Общая статистика (количество участников на каждом этапе)

## Важные замечания

1. **Токены на балансе контракта**: Перед вызовом `claim_reward` токены должны быть на балансе контракта. Issuer должен использовать `deposit` для пополнения баланса.

2. **Валидация вручную**: Issuer должен вручную проверять задания вне блокчейна перед вызовом `validate_task`.

3. **Одно задание на участника**: Каждый участник может подать только одно задание.

4. **Один токен на участника**: Каждый участник может получить только 1 токен после валидации.
